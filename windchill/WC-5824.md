# Business Requirement

Currently users can promote a WTPart from **INWORK → RELEASED** even when no compliance document is attached.

This has resulted in released parts entering production without regulatory approval documentation.

The system must prevent promotion when:

* WTPart type = MechanicalPart
* Lifecycle state changing to RELEASED
* No attached Compliance Document exists

User should receive a meaningful validation message.

---

# Acceptance Criteria

### AC1

Given a MechanicalPart

When user promotes it to RELEASED

And no Compliance Document is attached

Then promotion must fail.

---

### AC2

Given a MechanicalPart

When Compliance Document is attached

Then promotion succeeds.

---

### AC3

Validation message:

```text
Release blocked:
Compliance Document must be attached before releasing this part.
```

---

### AC4

Validation should work from:

* Promotion Request
* Workflow Task
* Bulk Promotion

Implement validator.

Pseudo-code:

```java
validate(object){

   if(object instanceof WTPart){

       WTPart part = (WTPart)object;

       if(isMechanicalPart(part)){

           boolean documentExists =
                checkComplianceDocument(part);

           if(!documentExists){

               throw ValidationException(
                    "Release blocked..."
               );
           }
       }
   }
}
```

# Developer Notes

Common Windchill pitfalls:

### Pitfall 1

Using latest iteration incorrectly.

Need:

```java
VersionControlHelper
```

to fetch latest iteration.

---

### Pitfall 2

Checking document on working copy.

Need:

```java
WorkInProgressHelper
```

---

### Pitfall 3

Promotion Notice contains multiple objects.

Don't assume:

```java
promotionNotice.getObject()
```

There may be:

```text
Part A
Part B
Document C
CAD D
```

Need to iterate through all promotables.
